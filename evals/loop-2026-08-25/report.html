advanced-skill-finder — Skill Description Optimization

Optimizing your skill's description. This page updates automatically as Claude tests different versions of your skill's description. Each row is an iteration — a new description attempt. The columns show test queries: green checkmarks mean the skill triggered correctly (or correctly didn't trigger), red crosses mean it got it wrong. The "Train" score shows performance on queries used to improve the description; the "Test" score shows performance on held-out queries the optimizer hasn't seen. When it's done, Claude will apply the best-performing description to your skill.

Original: Discover agent skills from the open ecosystem and load them either permanently or for a single session. Use when the user says "find a skill for X", asks "is there a skill that can...", names a skill or repository to try, or wants to extend agent capabilities. Also use before starting specialized or complex work — framework-specific implementation, deployment, testing strategy, document or data tooling — when no already-installed skill covers it. Check the available-skills list first, and search the ecosystem only if nothing there fits. Always offers a choice between installing and one-off loading before touching anything.

Best: Use this whenever the user is about to do serious, unfamiliar, or high-stakes work and would rather follow a proven external playbook than your improvisation — threat modeling and security review, testing strategy, big migrations and upgrades, infra/IaC and PR review, deployment, new frameworks, SDKs, APIs, or file formats. The strongest cues are situational, not the word "skill": "I've never done this at this scale", "I don't trust my instincts", "has someone written this down", "find something battle-tested / proven / repeatable", "set it up so it's there next time", "what tooling are you missing for our stack — go get it". Also use when they name a repo, author, or skill and want it found, judged, or vetted as safe to install. Search the open agent-skills ecosystem, check the source's reputation, then offer install-permanently versus load-just-once and let them pick. Not for authoring, listing, or deleting their own skills, or for following their team's internal docs.
